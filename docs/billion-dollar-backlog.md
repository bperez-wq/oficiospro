# Billion-dollar backlog

Este backlog no promete una valoracion especifica. Sirve para organizar apuestas compuestas que, si se ejecutan con traccion real, podrian aumentar de forma significativa el valor de OficiosPro.

## Estructura de evaluacion

Cada item debe registrar:

- Impacto.
- Esfuerzo.
- Riesgo.
- Metrica afectada.
- Dueno IA.
- Estado.
- Proximo paso.

## Modelos a evaluar si baja traccion

- Marketplace comision estandar: comision 9,5% + IVA, requiere volumen y automatizacion.
- Suscripcion especialistas: mensualidad baja por perfil premium, util cuando ya hay demanda real.
- Leads pagados por especialista: pago por lead calificado, requiere calidad alta.
- Plan empresa/comunidades: bolsa de creditos o plan mensual, mayor ticket y menor CAC.
- SaaS operativo para especialistas: agenda, cotizacion, formalizacion y cobro.
- Modelo institucional: digitalizacion, formalizacion y empleabilidad para municipios, OMIL, CFT o programas.
- Vertical B2B primero: empresas, comunidades y campos antes de hogar masivo.
- Freemium de perfiles: perfil gratis con upgrades de destacados/verificacion/prioridad.
- Hibrido: comision baja + planes empresa + perfiles premium + leads calificados.

## Regla de priorizacion

Subir prioridad si el item mejora directamente la North Star, desbloquea un cuello de botella real o reduce riesgo operacional. Bajar prioridad si solo mejora apariencia sin conversion, agrega complejidad o requiere aprobacion L3/L4 sin evidencia.

## Entrada desde salud del modelo

El reporte `reports/business-health/YYYY-MM-DD.md` alimenta este backlog. Cada alerta debe convertirse en una de estas salidas:

- ciclo Kaizen L2 si es mejora de bajo riesgo;
- experimento con guardrails si hay hipotesis de crecimiento;
- alerta de modelo si afecta unit economics, B2B-first, precios, comision o monetizacion;
- decision de Benjamin si cruza L3/L4.

No se sube una apuesta de backlog a ejecucion si el reporte declara `insufficient_data`, salvo que el objetivo sea mejorar medicion.
