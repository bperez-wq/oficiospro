# OficiosPro AI operating system

## Proposito

OficiosPro busca transformarse en una plataforma lider de servicios tecnicos, oficios, mantencion y especialistas, con posibilidad de escalar a Chile y LatAm mediante tecnologia, red de especialistas, formalizacion, reputacion, CRM, pagos y adquisicion organica.

Este sistema operativo define como Benjamin, ChatGPT, Codex, Claude y Grok trabajan en ciclos continuos para reducir el cuello de botella del fundador y mejorar la plataforma todas las semanas.

## Meta aspiracional

Construir una empresa con potencial de valoracion US$1B+ en 5 anos o menos. Esto no esta garantizado: depende de ejecucion, mercado, traccion, capital, equipo, foco operacional y timing.

## Principios

- La plataforma debe mejorar todas las semanas.
- Cada mejora debe tener una hipotesis, una validacion y una metrica esperada.
- Ninguna IA trata datos demo como reales.
- Ninguna IA cambia pagos, D1, Worker, comisiones reales, seguridad o promesas publicas sin aprobacion explicita.
- Los cambios deben trabajar sobre lo avanzado, no rehacer desde cero.
- Si una metrica contradice la estrategia actual, la IA debe levantar alerta y proponer experimentos pequenos.

## Flujo de trabajo

1. Observar: revisar metricas, feedback, CRM, errores, Search Console, comportamiento de usuarios y estado del backlog.
2. Diagnosticar: definir problema, causa probable, usuarios afectados y riesgo de no actuar.
3. Priorizar: ordenar por impacto, urgencia, esfuerzo, riesgo y dependencia de Benjamin.
4. Disenar solucion: elegir intervencion minima viable, alcance y criterio de exito.
5. Implementar: Codex o Claude ejecutan sobre la base existente, sin romper modulos criticos.
6. Validar: correr validaciones requeridas, revisar rutas afectadas y documentar resultado.
7. Desplegar: usar release gates cuando corresponda.
8. Medir: comparar metrica esperada versus resultado real.
9. Aprender: registrar aprendizaje, deuda y siguiente decision.
10. Repetir: preparar el proximo ciclo semanal.

## Responsabilidad sobre modelo de negocio

El sistema Kaizen IA de OficiosPro no debe limitarse a mejorar diseno, codigo, UX o funcionalidades. Tambien debe evaluar continuamente si el modelo de negocio esta mostrando traccion suficiente.

Si las metricas muestran baja traccion, baja conversion, poco interes de especialistas, baja demanda cliente, bajo uso de creditos, baja retencion o problemas de monetizacion, las IAs deben levantar alertas y proponer hipotesis de cambio de modelo.

Esto no significa cambiar el modelo automaticamente. Significa detectar senales y preparar alternativas estrategicas para revision de Benjamin.

## Senales de alerta

Las IAs deben alertar si se observa cualquiera de estas senales:

- Muchas visitas y pocos registros de especialistas.
- Muchos registros iniciados y pocas postulaciones completadas.
- Muchos especialistas registrados pero pocos clientes.
- Muchos clientes buscando pero poca cobertura.
- Baja conversion de Bolsa a solicitud.
- Baja disposicion a pagar creditos.
- Alto abandono en checkout.
- Mucho interes B2B pero poco uso hogar.
- Mucho interes de especialistas pero baja calidad de perfiles.
- Alto costo operacional por servicio versus comision 9,5% + IVA.
- Mucha friccion en formalizacion.
- Pocas solicitudes reales por comuna/oficio.
- Poca recurrencia.
- Baja retencion de especialistas.
- Bajo uso de Club Hogar o planes empresa.

## Como proponer cambios de modelo

Cuando una IA detecte baja traccion, debe responder con:

1. Metrica observada.
2. Senal de alerta.
3. Hipotesis de causa.
4. Riesgo si no se corrige.
5. Alternativas de modelo.
6. Experimento de bajo costo.
7. Metrica de exito.
8. Tiempo de prueba.
9. Recomendacion.
10. Que requiere aprobacion de Benjamin.

Ejemplo: si despues de 1.000 visitas a `/especialistas-fundadores` hay menos de 20 postulaciones completas, se debe testear captura de lead corto + WhatsApp + llamada operacional antes de seguir optimizando solo diseno.

## Regla de experimentos

No cambiar el modelo completo sin evidencia. Primero testear experimentos pequenos:

- Landing A/B.
- CTA distinto.
- Lead corto versus formulario completo.
- WhatsApp versus formulario.
- Especialistas gratis versus perfil premium.
- Plan empresa versus cliente hogar.
- Oferta por oficio especifico.
- Piloto por comuna.
- B2B versus hogar.
- Comision versus lead fee.

Cada experimento debe tener hipotesis, segmento, duracion, metrica, criterio de exito y criterio de abandono.

## Definicion de terminado

Un ciclo queda terminado solo cuando:

- El problema y la hipotesis estan escritos.
- El alcance esta acotado.
- Se respetaron modulos criticos.
- La validacion aplicable se ejecuto o se documento por que no aplica.
- El backlog queda actualizado.
- Hay commit claro si hubo archivos modificados.
- El aprendizaje y la siguiente accion quedan documentados.
